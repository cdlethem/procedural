# CP18 private field decision

Root retains a seed-only three-dimensional scalar field for public contract preparation.
The six dyadic samples independently calculated with a Python integer-hash/reference
interpolator match Java exactly. Lattice centers are0.5; repeated queries are pure;
small offsets straddling each of the three lattice planes give nearby values in the tested
cases. These checks distinguish negative-coordinate floors, axis hashing and interpolation
order; they do not establish the eventual full safe-integer domain.

The three native JAVA2D slices at depth0.25,0.5,1.25 show coherent curved stroke regions.
Moving depth changes their shape while every stroke origin stays fixed. The first two
slices visibly share broad directional organization; the larger depth edit produces a
more different pattern. Root did not see isolated random speckling or obvious field-grid
seams in this bounded study. The regular mark grid remains visible by design. No universal
isotropy or temporal smoothness metric is claimed from these still images.

The hemisphere study reuses the same field on actual x/y/z coordinates and changes their
color. Root observed broad blue/slate and ochre patches across the fixed point positions.
The dense center forms visible concentric rings because the authored latitude sampling
and mark sizes overlap. This is a presentation limitation of the private study, not
proof of a sphere mesher or high-quality point distribution. It does not establish a
native P3D workflow. Public acceptance should use existing native mesh infrastructure
for volumetric transfer, alongside a useful planar-depth editing workflow.

No octave count, amplitude, detail, hash or gradient-table control is needed for these
uses. Keep only the explicit seed and3D queries. User-supplied coordinate scaling and
translation control field scale and sampled slice. The examples do not establish public
artistic defaults or encouraged ranges. Do not reuse the probe's temporary +/-1e6 input
bound in the public contract; reconcile the safe-corner domain with GradientNoise2D01.

The proposed implementation uses12 integer edge gradients, the existing licensed lowbias32
mixer, a third hash stage and quintic separable interpolation. It deliberately does not
match Processing Perlin noise or the existing2D field at z=0. Preserve the2D operation
unchanged. No composite survey candidate becomes a whole-computation merge merely because
it consumes3D noise: placement, gating/remapping, orientation, strokes and cone geometry
retain separate remainder accounting.
