# Root decision: retain summed radial pull for contract work

All four predeclared JAVA2D renders completed through the established shared machine lease.
Root inspected every image and verified live source, JAR, runtime, generated-source, class
and image hashes. Exact configurations and raw RGB/pixel differences are in experiment.json.
The corrected private study passed its analytic assertions during actual setup. Earlier
unfinished worker drafts were corrected before any render; no failed render was removed.

The radius edit from120 to180 expands the deformation and creates overlapping folds across
most of the grid (mean RGB difference0.09885; changed pixel fraction0.30117). Power2 to0.5
produces smaller folded regions and a tighter pinch at the same radius (0.04817;0.15335).
The baseline remains legible as a grid interrupted by two rosettes. The transfer deforms
three retained closed-spline contours into looping/hooked shapes using the same function.
These are observed private-design results, not source reproduction or portable conformance.

Retain the capability: explicit local influence is a useful geometry control absent from
noise fields and raster resampling. Keep summed radial pull distinct from sequential push
and stochastic attraction. Drawing, grid/spline sampling and palette remain caller choices.
The source-inspired discontinuity is intentional and visible; name and teach the operation
as a folding/pinching pull, never a smooth or invertible deformation. Exact-center zero
is a proposed symmetry-preserving policy, not a claim that the surrounding field is continuous.

No public default, encouraged continuous interval or hard numeric bound is established.
Radius and power remain caller configuration; only the tested private examples are visually
reviewed. The larger radius demonstrates overlap and clipping risk rather than a universal
upper limit. Public validity, overflow handling, output ownership, allocation-free queries,
work limits, ordered accumulation and elementary-math policy still require a frozen contract.
The prototype's per-contribution addition into x/y is not yet a normative rounding order.

Next root records evidence-versioned candidate admission and freezes these decisions, then
Terra implements the Java core against independent fixtures. Native public edit/reset/save
and retained-geometry transfer must use that core. Private source is excluded from the
shipped package. Java remains21 operations; no new original recreation is counted.
