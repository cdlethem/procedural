# CP1 noise choice: root decision

Select the single-octave scalar source for the first example and proceed to formal contract
admission. Keep four-octave accumulation as an explicit exploratory composition, not hidden
behavior or an approved general FBM operation. This is a design decision about the example;
no public artistic default or encouraged parameter range is established.

Root inspected all four 640×640 images referenced by `measurements.json`. Each contains
25,600 separate straight strokes on fixed grid positions. In `single`, broad curved regions
of related headings are easy to follow; teal, yellow, red and navy bands cross the image.
`four` retains coherent regions but adds smaller directional changes and a more mottled
colour distribution, with more visible navy/red in this configuration. The two rotated
images preserve the same readable field-of-strokes mechanism while changing the arrangement.
Visible regular mark spacing is expected from the explicit grid. I did not see a distracting
repeated noise-lattice pattern that dominates these four probes. This is not proof of
isotropy across seeds, scales or all rotations.

The single/four RGB MAE is about 0.1615 unrotated and 0.1592 rotated, with about 91.5% and
91.3% of pixels changed respectively. These descriptive differences do not measure quality.
The chosen single-octave image makes the introductory mechanism legible; extra fine detail
is not necessary to establish this first capability. Exact metrics and image/source/config
hashes are generated by `measure.py`, not manually entered acceptance thresholds.

The registered experiment had four attempts, all successful. No reference corpus PNG was
available or used. This independently specified candidate field is neither Processing
noise compatibility nor an exact pelines reproduction. JAVA2D, the opaque background,
fixed alpha, centre-anchored unclipped segment geometry, example palette arithmetic and
chosen frequencies are explicit experimental choices. The probe's fixed coordinate window
and query loop are not a validated public implementation of the eventual full input domain.

Sol's semantic corrections are accepted: ordered hash mixing, descriptive gradient-noise
name, exact-safe lattice corners, explicit periodicity, full raw-to-[0,1] mapping, seed-only
field state, and allocation-free native scalar queries. Admit a new scalar-source dependency
with pelines capability provenance; do not falsely merge its composite consumer into this
algorithm. Preserve unrelated component accounting and CP2's distinct signed simplex source.

Still required: approved catalog contract and distinguishing vectors, all native ports,
parameter-edit/mark-transfer checks through the public implementation, target adapters,
and scoped reproduction. These four exploratory renders do not complete CP1 or any
four-target milestone.
