# Drawing contract review

Root integration with Sol, 2026-09-07. The draft is
[`drawing.fresh-raster-2d` v0.1.0](../catalog/drawing/fresh-raster-2d.json).
It is shared value/adapter infrastructure, not another surveyed generative operation.
No candidate is reassigned or falsely merged by this catalog addition.

Sol identified four consequential gaps; root accepted and integrated all four:

- Validate each record through every stage before moving to the next record. A later
  schema failure must not hide an earlier topology failure. All records still validate
  before a batch begins drawing.
- Separate static capability preflight from surface acquisition, readiness verification
  and native initialization. Classify and release acquired resources on each failure.
- Translate source alpha as opacity8/255 with an explicit numeric rule, rather than
  leaving normalized versus byte alpha to each adapter author.
- Use the existing `processing-android` target ID, with backend `ANDROID2D`, so shared
  target matrices do not accidentally create a fifth host.

The draft also fixes the proposed 4096-command batch limit as an engineering memory/work
policy, with exact frame-wide indices and no-op counting. Renderer families are JAVA2D,
Canvas2D, JAVA2D and ANDROID2D for Processing, p5.js, py5 and Processing Android respectively.
Every native profile status is unvalidated.

Verification completed: 11 schema cases; 12 catalog unit tests covering drawing and
existing operation catalogs; source bindings, duplicated schema consistency and catalog
checks. Fifteen proposed semantic cases distinguish inclusive limits, rounding onto a
limit, one-ULP excursions, canonical versus converted degeneracy, and invisible invalid
commands. They are not yet executed through a portable validator. Lifecycle fixtures
and complete semantic fixture review remain before freezing implementation assignments.

Sol's final direction review accepted the architecture/core semantics and retained draft
status. Root encoded dynamic margin/width rules as machine-readable objects and clarified
synchronous versus asynchronous render-error indices. Before implementation handoff,
add normalized output bits/alpha ratios and a non-square environment to semantic goldens;
add lifecycle fixtures for error precedence, batch boundaries, absolute/no-op indices,
terminal states, cleanup, native/end failures and exact-safe count overflow. These are
explicit next requirements, not evidence already claimed by schema validation.

The next continuation added 31 normalized goldens generated by an exact oracle, including
binary32 coordinate/width bits, binary64 alpha ratios, both non-square orientations,
signed zero and conversion overflow. Sol independently verified the initial 24 outputs
and all 256 opacity ratios; the tall/overflow cases address his subsequent coverage
requests. Catalog checks bind the generated artifact to its source inputs.

Twenty-one authored lifecycle scenarios now execute against a reference state model.
They assert errors/states and acquisition, release, transfer and native-command-attempt
counts, covering invalid-batch atomicity, prior-batch preservation, no-op indices,
terminal misuse, environment/preflight/acquisition failures, initialization/finalization
failures and exact-safe count boundaries via a test-only hook. Model events are simulated:
these results neither certify actual resource cleanup nor substitute for native tests.

Root closed Sol’s final model requests: retain the environment accepted by begin, test
active begin and pre-begin batch misuse, and verify fixture identity/version. Added a
non-square active-environment regression. All 21 scenarios pass. Root now accepts v0.1.0
as reviewed for portable implementation; all native backend support remains unvalidated.
