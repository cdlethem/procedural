## Installed prerequisites and first execution

Root installed the pinned Processing Android 4.6.0 release (`android-412`) and source
revision `363521a3d83982f540aeade89f3e5777de4226a5`, command-line tools 19.0,
platform 33 revision 3, build tools 30.0.3, emulator 37.1.11, platform tools 37.0.1,
Android 33 Google APIs x86_64 image revision 17 and Gradle 7.4.2. Exact archive/core
hashes and installed properties are generated by `tools/record_android_environment.py`
in `evidence/conformance/android-environment.json`. SDK licenses were accepted during
installation of these local development prerequisites.

The release templates specify AGP 7.1.0/Gradle 7.4.2 and SDK33; the actual bootstrap
APK builds with those versions and Java17. Build evidence is retained, including
the two diagnosed setup failures. The installed emulator's own help supports
`-accel off`; it is running with TCG and SwiftShader. ADB became reachable and
native logcat shows first-boot package/dex processing. This is progress, not yet
a completed boot or native drawing certification.

A premature install while the package service was only partially initialized failed
with PackageManagerInternal unavailable. The checked-in runner therefore requires
`sys.boot_completed=1` before installation/launch. Keep the existing emulator while
it makes observable boot progress; do not restart it simply because boot is slow.

Boot subsequently completed. `tools/run_android_bootstrap.py` installed and launched
the built APK successfully, and its actual PApplet reported API33, the expected
`processing.a2d.PGraphicsAndroid2D` and 32×24 dimensions. Result:
`evidence/conformance/android-bootstrap-runtime.json`. The bootstrap app is stopped;
the isolated emulator remains warm for the separately registered adapter validation.
KVM permission is therefore not currently a prerequisite blocker.
