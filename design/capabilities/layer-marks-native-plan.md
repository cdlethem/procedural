# LayerMarks native acceptance plan

Preregistered root plan; Java-only candidate workflow, no acceptance claim.
Artist task: substitute image snippets and generated content inside retained rectangular
partitions, and choose hard visibility, soft cutout coverage or a true two-input crossfade.
Motivation: maintainer composition request; eyes002 image/draw-callback content and existing
RetainedRectangles2D partition capability. No original sketch recreation is claimed.

Use actual packages/java-processing/examples/LayerMarks/LayerMarks.pde through the pinned
official Processing preprocessor, candidate source-built core+adapter JAR, JAVA2D density1,
720x480. No external assets; source picture is independently generated in the example.
Render through the shared machine lease and existing registered starter runner.

Native sequence: baseline CANVAS content; M -> LOCAL image snippets plus marks; M -> inward
24-pixel authored feather; M -> crossfade from canvas content to local content using the
authored horizontal weight ramp; M -> restored baseline; S -> cached displayed-image save.
Capture IDs baseline,local,feather,crossfade,restored. The24-pixel feather and ramp coordinates
are example choices, not recommended parameter ranges. This is five native captures plus
save, not a new renderer matrix. Repeat only for changed inputs or a concrete failed check.

Verify queued mode changes are actually painted, correct runtime class origins, retained
source/background pixels unchanged, all outside [36,36,684,444] pixels preserved, mode wrap
equals baseline, and saved pixels equal the cached displayed result without reconstruction.
Crossfade alpha arithmetic is separately covered by core fixtures; inspect this composition
for smooth content transition rather than a gutter that reveals the background.

Root visually reviews every meaningful mode and registers images in the central gallery.
Adapter native semantic checks establish isolated callback targets, preflight/error recovery,
empty output and coordinate behavior separately. This workflow does not establish arbitrary
polygon masks, automatic image-region detection, fractional transparent image resampling,
renderer portability or large-partition-count animation performance.
