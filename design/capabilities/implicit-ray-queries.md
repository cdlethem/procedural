# Bounded implicit ray queries

Root freezes the bounded CPU ray-query contract. Artist task: blend and cut implicit volumes and inspect their visible surfaces. The operation removes typed field evaluation, CSG sign handling, bounded stepping and normal estimation; returned hit records can be shaded in a p5 raster study. A local shader is an alternative. Changing blend width or a subtracting box is a meaningful edit; transfer to a perforated shell tests the same computation.

## Data and validation

One call contains an explicit scene tree, ordered rays, and all controls. Coordinates are right-handed world `[x,y,z]`; ray distance, radius, extents, `k`, `hitEpsilon`, and `normalStep` use the same world units. A leaf is exactly `{kind:"sphere",center,radius}` or `{kind:"axisBox",center,halfExtents}`. Binary CSG nodes are exactly `{kind:"union"|"intersection"|"difference",left,right}` or `{kind:"smoothUnion",left,right,k}`. The only transform is exactly `{kind:"translateUniform",translation,scale,child}` with finite `scale>0`. Radius, all three half-extents, and `k` are strictly positive. There are no empty scenes, materials, callbacks, arbitrary scaling, rotation, repetition, or optional defaults.

Every record is an ordinary passive object with prototype `Object.prototype` or null and exactly its declared string keys as own data properties. Arrays have the ordinary array prototype, exact dense length, own data elements and no extra own keys; symbols, extra keys, accessors and exotic ordinary carriers fail `INVALID_INPUT` without reading accessor values. **Proxy objects are outside portable interchange.** JavaScript reflection itself can invoke Proxy traps, so universal Proxy detection/rejection, a stable error code, and zero trap side effects cannot be promised for a supplied Proxy. Valid plain data require no user callback. Numbers are finite binary64; signed zero is captured as positive zero. The scene must be an object-identity tree: no cycle or shared scene record **or coordinate array**, even where the serialized JSON would look equivalent. Ray records and arrays are passive but may reuse equal numeric values; they do not alias output. Root depth is one, the deepest accepted node is depth 64, and depth 65 fails `LIMIT_DEPTH`. Visit the scene in preorder, left before right, and rays in input order. Full static capture/validation of all reachable supported input precedes cap and work checks. At most `maxRays` rays and `maxSceneNodes` scene records are accepted; both caps and `maxSteps`/`maxWork` are explicit safe integers, with `maxRays,maxWork>=0` and `maxSteps,maxSceneNodes>=1`. `maxDistance,hitEpsilon,normalStep` are finite and strictly positive. A direction with all three zero components is invalid.

Static failures return `INVALID_INPUT` (including bad tag, arity, nonfinite supplied number, zero direction, sharing/cycle), except a depth breach returns `LIMIT_DEPTH`. Validation traverses top-level fields in schema order, scene preorder, then rays in input order; the first fault in that order wins. After complete static validation, cap precedence is `LIMIT_RAYS`, then `LIMIT_SCENE_NODES`, then `WORK_LIMIT`. Reserve **before** direction normalization or field evaluation with `R=rays.length`, `N=scene-node count`, `S=maxSteps`, `W=BigInt(R)*(BigInt(S)+6n)*BigInt(N)`; fail if `W>BigInt(maxWork)`. Every field sample evaluates all scene nodes (no short circuit), so the reservation bounds at most `S` primary samples and six normal samples per ray. The fixed depth and node/ray caps also bound memory and recursion. Host allocation failure is not converted into partial results. Once work passes, normalize all ray directions in order, then trace rays in order; any nonfinite computed intermediate fails the whole call as `NUMERIC_OVERFLOW`. No partial result is published. Empty rays return `{results:[]}` after scene validation and caps with `W=0`.

## Field and binary64 arithmetic

Define `H3(x,y,z)=fdlibmHypot(fdlibmHypot(x,y),z)` using the already reviewed fdlibm two-argument helper. All expressions use binary64 round-to-nearest ties-to-even, strict left-to-right steps, no FMA/reassociation, and a finiteness check after each subtraction, multiplication, division, addition, or `H3`. Normalize every computed zero to positive zero. A nonzero direction's unit vector is each component divided by `H3(direction)`; a nonfinite or zero computed length is `NUMERIC_OVERFLOW`. For each noninitial point, compute each coordinate as `origin[i] + (t*unit[i])`, checking the product and sum separately. The initial point is the captured origin. Field evaluation visits both children of a binary node, left before right, on every sample.

For a sphere, set `q_i=p_i-center_i` in x/y/z order and `d=H3(q)-radius`. For an axis box, set `q_i=abs(p_i-center_i)-halfExtents_i`; `outside=H3(max(q_x,0),max(q_y,0),max(q_z,0))`, `inside=min(max(q_x,max(q_y,q_z)),0)`, and `d=outside+inside`. Hard union is `min(a,b)`, intersection is `max(a,b)`, and difference is `max(a,-b)`; equality chooses the left operand. For `smoothUnion`, compute finite `delta=a-b`, `absDelta=abs(delta)`. If `absDelta>=k`, return the hard minimum (left on equality). Otherwise compute `h=1-absDelta/k`, `m=min(a,b)` (left on equality), then `d=m-(((k*h)*h)/4)` in that order. The transform evaluates `p'_i=(p_i-translation_i)/scale`, then returns `scale*dChild(p')`. Its positive uniform scale preserves world units. A computed underflow-to-zero is retained as zero and is one reason this binary64 tracer does not certify exact intersections.

In exact real arithmetic, sphere/box signed distances are 1-Lipschitz. Hard `min`, `max`, sign reversal, and positive-uniform-scaled composition preserve a 1-Lipschitz field and the Boolean sign convention. They need not remain exact Euclidean distances. The smooth-union transition also preserves the bound: when `a<=b` and `0<=b-a<k`, `h=1-(b-a)/k`, so the partial derivatives are `∂d/∂a=1-h/2` and `∂d/∂b=h/2`. Both lie in `[0,1]` and sum to one; the symmetric case swaps them. Outside the transition one weight is one and the other zero. Continuity extends the bound across ties and transition boundaries. Thus a **positive exact** field is a conservative lower bound to its own zero set. The polynomial shape expands relative to hard union. Binary64 rounding, finite `hitEpsilon`, representation collapse and finite step count invalidate any claim that a returned hit is an exact root or that all thin features will be found.

## Trace, normal, and output order

`maxSteps` caps **primary field samples**, not advances. For each ray, start at `t=0`, sample the field, and increment `samples`. At the initial sample, `d<0` gives `inside_start` even though `d<=hitEpsilon`. Otherwise any `d<=hitEpsilon` gives `hit_epsilon`. A later negative sample is `hit_epsilon` with `overshot:true`; all other records have `overshot:false`. For a positive sample outside epsilon, test in order: (1) if `t===maxDistance`, `miss_range`; (2) if `samples===maxSteps`, `miss_steps`; (3) set `remaining=maxDistance-t`, and if `d>remaining`, `miss_range`; (4) compute `next=t+d`, except set `next=maxDistance` directly when `d===remaining`; if `next===t`, `miss_stalled`; if `next>maxDistance`, `miss_range`; otherwise set `t=next` and sample again. Thus an exact boundary is sampled once and a boundary hit wins; a positive boundary sample is `miss_range` even when that sample also exhausts `maxSteps`. A single positive initial sample with `maxSteps=1` is `miss_steps` before testing its proposed advance. No field evaluation occurs at an unsampled range endpoint.

Every result has the same keys shown in the schema. `traveled`, `position`, and `fieldValue` describe the **last actual primary sample**, including a miss. `distance` is that sampled `t` for either hit and `null` for every miss. `samples` counts only primary field evaluations; `normalSamples` counts six or zero extra scene evaluations. No implicit hit location interpolation occurs. `position`, `normal`, and all output arrays are new detached values. Results preserve ray order.

Every hit requests a normal, but the result distinguishes an estimate from an undefined differential. The base field evaluation carries a conservative `nonsmooth` flag: a sphere is nonsmooth at its center. For a box with every `q_i<=0`, find the largest `q_i` with x-before-y-before-z tie order; it is nonsmooth if at least two axes attain that maximum or if the selected axis has `p_i===center_i`. A box with any `q_i>0` is smooth at that sample. Hard CSG is nonsmooth at an exact equal-operand tie or when its selected child is nonsmooth. A smooth union propagates nonsmoothness from both children when `absDelta<k`, or only the selected child outside that transition. A transform passes the child flag. If the base flag is true, return `normal:null`, `normalStatus:"undefined_nonsmooth"`, `normalSamples:0`. This explicitly makes a box edge/corner and a touching hard-CSG seam undefined even though a bisector could be drawn. Otherwise sample the field at `p+h*axis` then `p-h*axis` in x, y, z order, six samples total, with checked coordinate arithmetic. For each axis compute `g_i=((fPlus-fMinus)/normalStep)/2`, checking each step. Let `gLen=H3(g)`. If `gLen===0`, return `normal:null`, `normalStatus:"undefined_zero"`; otherwise divide each `g_i/gLen` and return `normalStatus:"estimated"`. Nonfinite offset, sample or gradient arithmetic is `NUMERIC_OVERFLOW`, not an undefined normal. This is a finite-difference **estimate** at scale `normalStep`; it does not claim a unique mathematical normal at all CSG features.

Misses always have `normal:null`, `normalStatus:"not_applicable"`, `normalSamples:0`. The status and exact count fields compare exactly. Position, distance, field value and estimated normal receive explicit per-field numeric tolerances in cross-target fixtures; the JavaScript reference must match the frozen fdlibm/order profile. No global geometric epsilon is applied beyond the caller's positive `hitEpsilon`.

## Evidence limits and root review points

The draft vectors cover analytic axes, CSG signs, smooth-union midpoint, uniform scale, tie normals, boundary/sample/step precedence, finite overshoot, stalled addition, static/cap/work precedence, depth, and numeric overflow. A future native study should render an anisotropic two-volume silhouette and occlusion, vary `k` and a subtracting box, transfer a scene independently, retain hit mask/depth/status counts, and shade with asymmetric normal colors. Its pixel evidence would be specific to the pinned p5/browser profile and would not establish GPU cross-driver identity. No isosurface, secondary ray, shadow, mesh/SDF interop, fabrication, or source recreation is included.

Root has approved the proposed `axisBox` and `translateUniform` tags, conservative undefined normals at exact box/CSG ties (with no extra normal samples), and boundary-before-step priority when both limits coincide. These remain proposal semantics until the catalog and fixtures are frozen by root. The remaining review issue is whether the representation and numeric-oracle split below gives target ports sufficient independent evidence without claiming exact cross-runtime pixels.

## Fixture split and analytic audit

[The catalog-shaped proposal](catalog-proposal.json) follows the frozen H1 metadata layout while keeping `status:"proposal-only"`. [Exact fixtures](fixtures-exact-draft.json) contain 29 full-JSON cases, including errors, category/count precedence, CSG signs, the subnormal overshoot value, and the large-`t` stall. [Toleranced fixtures](fixtures-tolerance-draft.json) contain only two numerical cases: a positive initial epsilon field value with absolute tolerance `2e-16`, and the off-axis finite-difference sphere normal with per-component absolute tolerance `1e-12`. Both still compare status, nulls, counts and all other numeric fields exactly. The [master draft](fixtures-draft.json) retains all 31 expected records without changing their values; it is the source of the split, not an additional shared fixture set.

The distinguishing calculations are independent of a tracer implementation. For the axis sphere, `d(-3,0,0)=3-1=2`, so the first advance reaches `(-1,0,0)` and the central x difference is `(-0.25-0.25)/0.5=-1`. The axis box has the same two samples. A child unit sphere under translation `[3,0,0]` and scale `2` is a world sphere centered at `[3,0,0]` with radius `2`, so the ray from origin samples `d=1` then `d=0` at x=1. At the hard union contact of unit spheres centered at x=±1, both operands are zero and the exact tie makes the differential undefined. At their smooth-union midpoint with `k=2`, `h=1` and `d=0-2/4=-0.5`; symmetry makes the six-sample central gradient exactly zero. For the difference fixture at x=1, outer `a=-1`, subtractor `b=-0.5`, hence `max(a,-b)=0.5` (outside the cut). At x=-1.5, outer `a=-0.5`, subtractor `b=2`, so the returned `inside_start` field is `-0.5` and the sampled x normal is -1.

The off-axis normal fixture starts exactly on a radius-5 sphere at `(3,4,0)`. With `normalStep=1`, its sampled gradient is `((sqrt(32)-sqrt(20))/2,(sqrt(34)-sqrt(18))/2,0)`; normalization gives approximately `(0.5978936098905061,0.8015754682199919,0)`, deliberately distinct from the analytic sphere normal `(0.6,0.8,0)`. The initial positive epsilon fixture has `d=|0.995-2|-1=0.004999999999999893` in binary64, so it terminates before advancing. Both the exact-boundary-hit and positive-boundary-miss fixtures sample `t=maxDistance` once; the positive boundary sample is `miss_range` even when it is sample `maxSteps`. With one initial positive sample and `maxSteps=1`, `miss_steps` wins before a proposed advance is considered.

The finite overshoot fixture uses the smallest positive binary64 radius `5e-324` at center x=1. At origin, `1-5e-324` rounds to `1`; the first step lands at the center, where `d=-5e-324`, so it is a later `hit_epsilon` with `overshot:true`, not an inside start. The stall fixture starts from `(0,1,0)` toward a sphere centered at `(10^16,3,0)`, radius1. `H3(10^16,2,0)-1` rounds to `10^16`; the next sample has `d=1`, while binary64 spacing at `10^16` is2, so `10^16+1` ties back to `10^16` and returns `miss_stalled` after two primary samples. The exact work pair has one ray, three scene nodes and four allowed primary samples: `1*(4+6)*3=30`; budget29 fails and budget30 passes. One sphere wrapped by63 transforms has root-to-leaf depth64 and is accepted, while one more wrapper yields `LIMIT_DEPTH` before caps/work.

The pinned repository `fdlibmHypot` helper was used only to cross-check the expected binary64 stall, subnormal overshoot, epsilon value and off-axis normal; the fixture expectations above follow from the stated geometry and arithmetic independently. No H2 core or renderer exists yet.
