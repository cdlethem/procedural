# CP12 reconsideration after Java 0.15

Root retains the CP12 deferral and moves the current buildout to the deferred I2 port batch.
This is a scheduling decision, not a keep/merge/reject adjudication of venas#0. The corpus
still has a real unsupported band-constrained traversal; neither GradientPath2D nor
LinePool2D supplies it. Do not count venas as recreated.

Root reread the complete checked-in venas note and pinned PDE at
69bdd8513e4482a5e6018e36887d4bc208660eb5. Evidence identities and measured substitutions remain
in cp12-noise-band-evidence.md. The note describes winding contour-like bands and strong
whole-scene changes with tolerance and attempt count. The source has ten million proposals,
strict acceptance against each starting noise value, and different heading updates on
acceptance versus rejection. Its global seed is not passed to randomSeed/noiseSeed.

The artist task is valuable: keep winding strokes close to a chosen scalar level, then
restyle them. But portable field behavior, proposal policy, tolerance evidence and bounded
retained output remain unresolved. Adding a generic callback would hide those decisions;
substituting marching squares or noise-heading integration would change the computation.
The recently delivered line-pool mechanism does not resolve these uncertainties.

Coverage before/after this decision is unchanged: zero demonstrated CP12 originals, one
projected original (venas), and no independently established second computational pattern.
The earlier three-sketch cohort demonstrated existing composition without new core APIs;
line-pool then closed a different concrete algorithmic gap. There is enough delivered Java
breadth to begin the explicitly deferred portability work. This is root's design/economic
judgment, not an inference that a rare technique lacks value or an estimate of future cost.

Reopen CP12 in a bounded later capability batch when a prototype establishes a clear editable
interface and work/output behavior, or computation-level transfer evidence improves its case.
No new corpus search or render is required for this decision. Preserve the original evidence
and ledger state. Next: placement/filter ports first, with frozen shared semantics and native
PlacementMarks validation before claiming target support. Recipes and MCP remain downstream.
