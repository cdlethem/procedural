# CP21 admission: retained supplied rectangle edits

Root accepts the operation boundary for production contract work, not implementation or
release support. Private evidence: evidence/parameter-experiments/cp21-retained-cuts/decision.md
and selected-edit-native.json. Source/note hashes: cp21-gap-source-bindings.json.

Artist task: select one live region, split it at a supplied coordinate, keep unrelated
regions stable, and decorate or explicitly remove regions. The operation owns membership,
identity allocation, ordered replacement, valid bounds and atomic edit validation.
It removes more than rectangle arithmetic: interactive sketches otherwise repeatedly
maintain stale IDs, parent replacement and stable associations with color/content.

One binary cut expresses both aligned unequal quadrants and independently staggered
secondary cuts through composition. Keep cut selection and coordinates caller-supplied.
Do not add random bias, ratios, four-way modes, implicit omission, point hit-testing,
selection UI, history/undo, generic trees, rendering or thread synchronization.

Existing QuadrantPartition2D and BinaryCellPartition2D retain their seeded immutable output
contracts. They remain convenient generators. Do not change their stream/domain/order to
make them editable. The new stateful object offers an explicit editing entry point; it is
not a replacement or source-compatibility alias.

This is a capability-dependency admission motivated by griton#0, not a merge of that
composite source candidate. griton includes nested-random selection, three ratios,
orientation-dependent omissions and unrelated drawing; their corrected source behavior
is recorded in cp21-next-capability-direction.md. pliegues provides supporting prose/source
evidence but has no frontmatter candidate ID. Its aligned cuts demonstrate transfer;
no invented pliegues#0 enters the ledger.

Private views show aligned/staggered partitions, independent line decoration, holes and a
local selected-cell cut. Callback checks establish unrelated object identity, selection,
cut/removal and reset. These justify the boundary; production exact fixtures, native public
workflow and extracted distribution still must pass. No new original recreation claimed.

Production design decisions: finite binary64 bounds with finite positive extents; absolute
strictly interior cuts; signed-zero normalization; monotonic safe-integer identities;
ordered live leaves only; snapshot exports are detached, no restore/undo contract; single
edits validate completely before mutation. Lookup and mutation should be expected O(1)
with ordered-map storage; full snapshots cost O(liveCount). No preventable copying of all
leaves on each cut. Work/identity ceilings are representation, not artistic recommendations.
Root will write exact contract and focused deterministic command fixtures before code.
