# Root admission: seeded mutable line-pool growth

Root admits one operation candidate for contract preparation, grounded in the exact brotes
2019 source audit and the five-case line-pool-controls experiment. This is not a frozen
contract or implementation approval. Sol remains paused by maintainer instruction.

Artist task: generate branching strokes by repeatedly cutting existing segments, then draw
or restyle the resulting segments independently. The operation removes selected-worklist
mutation, first/repeated-cut transitions, child creation and deterministic termination.
Endpoint branching does not supply these semantics. A general grammar or callback policy
would add concepts without evidence and is excluded.

## Boundary

Inputs: one seed segment, RNG seed, attempted-work budget, first-cut angular scale, and
minimum cuttable segment length in caller coordinate units. The last input makes the
source's fixed4-unit stopping length explicit so changing coordinate scale does not silently
change detail. It is a geometric termination/resource input, not a newly measured artistic
range. No default or recommended range is established for any field. Contract design must
resolve exact numeric domains, RNG, portability and errors before implementation.

Output: final ordered segment endpoints, divided flags, attempted/successful/skipped counts.
Inputs are copied. During construction a selected segment's endpoint can change; after
construction output is retained and detached. Append index supplies stable identity within
one result, not ancestry or a geometric junction graph. Do not promise that all prior child
attachments move when a parent is shortened again. Zero work returns the original stroke.
A short selected line consumes an attempt. At most two segments append per successful cut.
One invocation is one pool; independent source pools are composed by the caller.

Preserve inspected source selection and first/repeated-cut policies for this operation's
version; do not expose source distributions as a policy bag. Source-host RNG compatibility
versus explicitly independent portable RNG remains a numeric specification task, not an
unresolved choice about which computation this operation represents.

## Candidate accounting

2019/generativos/brotes#0 is a component extraction from the described composition. The
retained component is the active mutable pool transition, not the report's inaccurate
1–3-child shorthand or a general L-system. Caller seed placement,30 independent pools,
random RGB colour, alpha/additive drawing and tip dots remain example composition. Source
unreachable branch and unused rendering imports are excluded; unused active RNG draws must
be accounted for by the eventual declared RNG policy. CP6 endpoint trees and2020 brotes
interior-attached recursive trees remain separate, not absorbed by this admission.

## Meaningful edits, transfer and limitations

Observed count and angle comparisons in line-pool-controls/decision.md motivate attempted
work as budget and angular scale as an independent visible control. Retained output supports
style changes without regeneration. Required next acceptance: a second seed/stroke transfer,
full source30-pool workload with recorded costs, and a useful editable native example.
Neither is complete yet. No added recreation coverage is claimed; brotes is projected only.

All numeric/state contracts, distinguishing fixtures and target support remain required.
Java-first delivery is allowed, with other ports explicitly deferred. Source-derived code
must retain MIT provenance. No public alias or universal branching facade is admitted.
