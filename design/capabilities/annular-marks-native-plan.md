# AnnularMarks native acceptance plan

Candidate workflow; no acceptance yet. Root owns the PDE and native review. Use the
existing pinned P3D runtime and one shared machine render lease. Compile through the
official Processing preprocessor; do not substitute the private study renderer.

Run real queued keys `wwddffccm0s` after initial draw. Record baseline, wide, width-restored,
deep, depth-restored, facets, facets-restored, recolored, colors-restored, arrangement,
and reset frames. The five restored states must equal the baseline pixels; each structural,
color or arrangement edit must differ. Inspect the five distinct changed outputs and
baseline, registering accepted candidate views in the centralized gallery.

Snapshot the retained mesh identity and exported values around color/arrangement/reset
edits. They must remain unchanged; width/depth/facet toggles must rebuild exactly once
per key. Expected meshBuilds after all keys:7 (setup plus six geometry toggles).
Saving must use displayedFrame without a redraw or mesh build, and the saved PNG must
match the cached image and current framebuffer after a quiet interval. Verify P3D and
density1 in the actual runtime. Preserve stderr and exact source/runtime/artifact hashes.

Pure fixture and ownership checks are separate prerequisites. Native appearance does not
prove error precedence or finite-range robustness. Once accepted, run this same workflow
from the extracted distribution and establish the actual core JAR origin. Do not claim
original recreation or non-Java support from this example.
