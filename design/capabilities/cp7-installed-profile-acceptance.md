# Installed ProfileMarks acceptance

Root will validate the actual officially preprocessed PDE and its editable Java tab
against the extracted Java 0.7.0 JAR. The shared core vectors and native ownership tests
already pass. This next check establishes a scoped Processing P3D workflow, not source
pixel reproduction, hardware coverage or support for deferred ports.

The selected mechanisms are connected circular bands (`cilindros`), caller-controlled
nonconstant radii (`fieeee`), and ordered axial band metadata (`Circo`). The complete
[source boundary review](cp7-profile-neighbour-boundaries.md) and accepted private
comparison explain the extraction and exclusions. The new example uses the public core,
retained flat normals, palette sampling and explicit local-to-canvas transforms.

One bounded attempt will draw the following states through real `keyPressed` events.
All images are 640 by 640 at density one. The starting profile is a capped cylinder.

Then `S` must save the displayed canvas without causing another draw during the registered
quiet interval. Total actual submissions must be 17,392 normals and 52,176 vertices.
The probe intercepts the actual PApplet normal/vertex calls; mesh face counts alone do
not establish submission. Core code must load from the supplied installed JAR. The plan
also binds generated PDE classes, helper classes, probe, source tabs, JARs and build reports.

Profile, palette and arrangement selection must retain the composition object. Subdivision,
cap and reset controls must rebuild it. Each reset image must match the baseline exactly;
selecting a different active profile while the trio is displayed must not change its image.
The saved image must match the final displayed reset. Geometry hashes accompany the
state records so colour changes can be distinguished from geometry regeneration.

Root will inspect the rendered images for distinct cylinder/waist/point silhouettes,
coarse facets, endpoint closure changes, recolouring of the same geometry and three
separately positioned forms. A back-facing cap may have no visible effect from this camera;
its removal still requires exact mesh metadata and draw-count evidence. No arbitrary
pixel threshold will stand in for this review.

The executor will hold the single render lock and allow one 180-second process-group
attempt. It must retain stdout, stderr and a terminal result on failure. The existing
software-context policy allows only empty stderr or the complete previously observed
seven-line Mesa/EGL/X11 shutdown sequence; other warnings fail the attempt. This is a
scoped software P3D context with known lifecycle diagnostics, not clean shutdown or
hardware acceleration certification. Failed or completed attempts will not be overwritten.
