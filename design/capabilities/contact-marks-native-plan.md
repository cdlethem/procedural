# ContactMarks native acceptance plan

Candidate workflow, no native acceptance. JAVA2D640x640density1. Ten supplied connectors
point toward an interior position; four supplied polygon edges are obstacles. ContactMarks
uses the new first-contact operation and existing Java2DLayers, not custom intersection code.
Colors and endpoint marks use returned obstacle identity. Misses remain in the result and
are deliberately omitted from this drawing. Ordinary segment drawing is the only glue.

Actual event sequence nnc0s: baseline, shifted obstacle corner, restored corner, recolored,
reset. Retain query identity/data and sourceBuilds1 throughout; contactBuilds1,2,3,3,3;
displayBuilds1..5. First two edits replace contact objects; appearance edits retain them.
Assert source/result parameter/point/obstacle identity against exact rational oracle. Baseline,
restored and reset pixels equal; shift and palette edits visible. Cached save must equal final
frame and cause no computation/redraw during300ms. Root views baseline/shift/color images.

A separate native ray-web transfer is still required before accepting the operation's artist
capability. Private Python-precomputed views do not establish production Java transfer.
Check newcore fixtures/carriers/ownership plus unchanged clipper regressions and bounded
performance before distribution integration. No upstream full-sketch recreation claim.
