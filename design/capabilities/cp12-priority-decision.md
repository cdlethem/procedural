# CP12 priority decision: defer public band-walker work

Root defers CP12 after reading the complete venas report, pinned source, Luna's identity/
variant/neighbour brief and the marginal coverage screen. This is a development priority
choice, not a final candidate rejection, a rejection of contour-like art, or an assertion
that only one corpus sketch uses this technique. Leave the candidate ledger unadjudicated.

A band-constrained walker removes real algorithmic burden and enables a distinctive task.
But current evidence establishes only one projected original and no second independent use.
Recreation depends on decisions about nested proposal randomness, accepted/rejected heading
updates, field semantics, tolerance and attempt versus output bounds. The source's large
workload reinforces the need for an empirical prototype; it is not itself proof that every
implementation would be expensive. No generic steering framework or special-case scene API
is justified to manufacture broader coverage.

Before paying that cost, assess existing package composition against a small cohort of
originals. The library already supplies subdivision, point filtering and Delaunay topology.
We should learn whether those remove the defining algorithms of complete sketches and which
remaining reusable work actually prevents recreation. This makes the maintainer's coverage
measure concrete and avoids adding operations before measuring current capability.

Reopen CP12 when a bounded prototype demonstrates a clear artist interface and useful band
behavior with explicit work costs, or additional computation-level evidence improves its
transfer case. A rare idiom can still merit admission without a large count. Its evidence,
known gap and roadmap place remain preserved; no implemented capability has been removed.
