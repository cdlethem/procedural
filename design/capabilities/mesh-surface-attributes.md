# Mesh surface attributes

Root freezes the portable surface-attribute operation for implementation. A p5 Geometry wrapper stays private to its example; target acceptance remains pending.

## Artist task, alternative, and evidence

An artist has indexed triangles from a radial profile, extruded polygon, or transported ribbon and wants the same geometry lit smoothly or with hard faces, plus an intentionally placed texture. The computation removed is face-normal construction, smoothing membership, vertex duplication at a sharp group/UV seam, and stable source-to-output indexing. The artist still chooses mesh shape, corner UVs, texture image, camera, lights, material, and timing. Existing mesh producers supply positions and triangle indices, but their per-face normals (where present) do not solve per-vertex smoothing/seams. Calling p5 `computeNormals(SMOOTH)` is an alternative for simple display, but its host-specific coordinate-based welding and index rewriting are unsuitable as the portable seam policy. No generic mesh has a unique UV chart, so caller-supplied **per-corner** UVs are the only UV input in H1.

The corpus record `joshua-davis-swarm-vertex-textures` links [Davis's *Swarm Vertex Textures*](https://joshuadavis.com/Swarm-Vertex-Textures/), whose artist page identifies behavior mapped to 3D texture but gives no reusable UV or normal algorithm. `deskriptiv-living-mushtari-a9482a8` links [Living Mushtari](https://deskriptiv.com/living-mushtari), whose project page describes recursive geometry and material variation in a fabricated wearable. These support the importance of textured/lit 3D presentation as an artist task; this contract does **not** recreate either project's motion, growth, texture, fabrication, or material process. The original study should visibly edit radial-profile shape while holding an asymmetric image fixed, edit image while holding geometry fixed, and transfer to an independently constructed extrusion or ribbon with new UV corners. These are design tests, not claimed corpus recreations.

## Input/output and coordinate convention

Input exactly `{positions,triangles,normalMode,smoothingGroups,cornerUVs,maxVertices,maxWork}`. `positions` is a dense array of finite binary64 `[x,y,z]` points, including unused points if supplied. `triangles` is a dense array of `[i,j,k]` source-position indices. Each index is an integer in `[0,V)` and all three indices in a face must differ; otherwise `INVALID_TOPOLOGY`. `normalMode` is exactly `"flat"` or `"smooth"`. `smoothingGroups` is a length-`F` array of nonnegative safe integers, required and validated even in flat mode, where it has no effect. `cornerUVs` is either `null` or a length-`F` array of three `[u,v]` corners per face; both components must be finite in `[0,1]`. `null` is untextured. UVs use an upright image convention: `u=0` left, `u=1` right, `v=0` top, `v=1` bottom. This is caller/source data; the pure core never flips or wraps it. Geometry uses caller right-handed local xyz; `[i,j,k]` outward direction is `(p_j-p_i) × (p_k-p_i)`. There is no winding repair, coordinate weld, UV synthesis, tangent, color, material, ambient RNG, clock, renderer, or retained mutable state.

Output exactly `{positions,triangles,normals,uvs,sourceVertexIndices}`. All fields are detached plain arrays, `uvs` is `null` iff input UVs are `null`, and each output vertex has one copied position, one unit normal, optional one UV pair, and one source index. Output triangles preserve input face and corner order and point to output vertices. Unreferenced source positions never appear. Empty faces are valid: empty output arrays (and `uvs:null` or `[]` according to input), after validating positions and paying `V` work. Exposed `-0` is always `+0`, including copied coordinates and UVs. No hidden rational metadata or aliases.

Flat mode emits three fresh vertices per face, in face-then-corner order, even when two corners from different faces have the same source index and UV. Each of the three vertices receives that face's unit normal. Smooth mode first assigns each source-position index and smoothing-group pair one normal from its incident faces. The aggregate is the **face-order sum of unit face normals**, with one contribution per incident face, then normalized; no area or angle weighting. Because indices within a face are distinct, a face contributes once to each of its three keys. A zero represented sum is `AMBIGUOUS_NORMAL`. Finally traverse face corners in original order; create an output vertex on the first encounter of `(source index, smoothing group, exact represented UV pair)`, and reuse that output index on later encounters of the same key. With `cornerUVs:null`, the key has one untextured sentinel. Normalize UV signed zero before keying. UV seam twins with one source index/group receive identical normal values but distinct output positions/UV entries. Different source indices are never welded even if coordinates and UVs match. Equal-weight smoothing is intentionally triangulation-dependent.

## Arithmetic and deterministic failure order

Validate all record keys/descriptors and all nested ordinary dense arrays, scalar domains, index ranges, pair/triple lengths, UV coverage, and repeated-corner topology before budget or geometry. Proxies are outside the portable carrier domain; no coercion, accessors, sparse arrays, extra keys/symbols, defaults, or input mutation. Validate fields in the input schema order; report malformed shape/value as `INVALID_INPUT`, except in-range repeated source index in one face as `INVALID_TOPOLOGY`. An out-of-range/noninteger index is `INVALID_TOPOLOGY`, because it cannot name a vertex. This includes a face referring to a nonexistent position. `V`, `F`, and each nested array length are at most `2^31-1`; `maxVertices` is integer `[0,2^31-1]`, and `maxWork` nonnegative safe integer. Compute `O=3F` as BigInt. After all static checks, if `O>maxVertices`, throw `OUTPUT_LIMIT`, even when smooth mode would emit fewer vertices. Then compute `W=V+27F` as BigInt; if `W>maxWork`, throw `WORK_LIMIT`. The vertex cap is deliberately conservative and independent of actual seam reuse. Both checks precede exact dyadic geometry work and output allocation. Host resource exhaustion is a host error, not a contractual allocation guarantee.

For faces in ascending index order, convert supplied finite binary64 positions to exact dyadics privately and test all three exact components of `(p_j-p_i)×(p_k-p_i)`. If all are zero, throw `DEGENERATE_FACE` **before any rounded difference/cross operation for that face**. Otherwise evaluate rounded binary64 primitives in this exact sequence, checking finiteness after each: `a=(p_j-p_i)` componentwise x,y,z, `b=(p_k-p_i)` componentwise x,y,z; `cx=a_y*b_z - a_z*b_y`, `cy=a_z*b_x - a_x*b_z`, `cz=a_x*b_y - a_y*b_x`, with each multiply and subtract checked. A nonfinite primitive gives `NUMERIC_OVERFLOW`. If the resulting represented cross vector is all zero, throw `REPRESENTATION_COLLAPSE` (the exact cross was nonzero). Otherwise compute `length=fdlibmHypot(fdlibmHypot(cx,cy),cz)`, check finite and positive, then divide each component by `length` once in x,y,z order with finite checks and signed-zero canonicalization. A nonfinite length or quotient is `NUMERIC_OVERFLOW`. This specifies behavior for tiny cross products and large finite components without an epsilon.

Complete all face normals before smooth aggregation. In smooth mode, visit faces in ascending order and corners 0,1,2, adding each face's unit normal to the per-`(source index,group)` x,y,z running sum with each binary64 addition checked for finiteness. The three component additions are x,y,z order. Normalize group sums in first key-encounter order using the same nested fdlibm hypot and component division. If all represented components are zero before normalization, throw `AMBIGUOUS_NORMAL`; nonfinite sum/length/quotient is `NUMERIC_OVERFLOW`. Thus a later face's numeric error precedes a group ambiguity, and the first failing face/group under those phase orders wins. No fallback normal or epsilon is used. General non-axis normals compare with absolute tolerance `1e-12` per component in fixtures; topology, copied positions, UVs, source indices, axis normals, error codes, and ownership compare exactly.

The deterministic reservation `V+27F` counts a conservative linear amount of validation/face/seam work, not each BigInt operation or host time. It is charged in full before geometry. Worst storage is `O(V+F)` for validated input references, face normals/group sums, and at most `3F` output vertices; a map keyed by integer source/group and exact canonical UV bits may accelerate reuse, but map order cannot affect output order. Geometry computation is linear in faces and emitted corners aside from exact arithmetic bit cost. This limit does not promise GPU allocation or a frame rate.

## First native p5 study boundary (after root freeze)

The first p5 study can privately build a new `p5.Geometry` from the detached output, copy positions/face indices/normals/UVs into p5 carriers, and call `model()`. It must not call `computeNormals()` or weld positions. It should use `textureMode(NORMAL)`, an asymmetric labeled 2×2 source texture, a fixed oblique camera and explicit light/depth, with a visible UV seam, flat/smooth switch, and a cap group. On each geometry or UV revision create a new geometry and call `freeGeometry(old)` before dropping the previous cached handle; snapshot the complete portable model and ensure save/reset/reload replay. One transfer must accept an extrusion or transported ribbon with independently authored corner UVs. An untextured path skips texture binding. The wrapper is private until a separate adapter contract/acceptance is reviewed. Negotiate WEBGL and 32-bit element indices when output indices exceed 65535 (`UNSUPPORTED_INDEX_WIDTH` if unavailable); a default study may set `maxVertices<=65536`. Context loss/recovery must rehydrate from the retained portable data or be explicitly scoped unsupported in the native result; neither the pure core nor a static image proves it. Document whether the pinned p5 renderer flips its physical texture pixels to honor the portable `v=0` top convention. No general GPU pixel identity, transparent sorting, material system, or external artwork recreation follows from this stage.

## Analytical oracle inventory

The draft fixture file covers +Z/reversed winding; differing-area 90° faces so equal-weight smoothing differs from area weighting; separate groups; an exact UV seam twin with one reused corner; equal coordinates with distinct source indices; untextured and empty geometry; exact collinearity ahead of rounded overflow; tiny nonzero cross underflow; finite cross components whose nested length overflows; negative/noninteger/out-of-range/repeated indices; partial/out-of-range UV and malformed groups; conservative output cap/work precedence; detached/passive carriers. A native runner later needs structural model/UV records before pixel judgements, geometry/texture independent edits, an asymmetric texture orientation probe, a transfer mesh, lifecycle checks, and explicit context-loss scope.

**Root review point:** this proposal chooses `OUTPUT_LIMIT` before `WORK_LIMIT` after complete static validation. If root wants the two budget errors in the other order, freeze that once in the catalog and fixtures before implementation; no target should infer it locally.
