# Fractal flame contract review

Root freezes the `fractal.flame-accumulate-2d` contract for the first I-family slice.
The design proposal (`.work/expansion-full/i-family-design.md`) and this review record
the frozen choices before implementation; the shared exact-json fixtures contain only
exact outputs and error codes, none generated by the implementation under test.

Resolved choices:
- One bounded operation, `fractalFlameAccumulate2D`, a pure function of its input that
  streams the iterate into a bilinear density buffer. No persistent state, no
  materialized point sequence.
- Bilinear splat (scatter) as the frozen first-slice reconstruction kernel, distinct
  from the accepted gather operation `bilinear-raster-remap`. Boundary sub-cells are
  clamped (discarded, not redistributed), so a point in the last row/column deposits
  less than full mass; the exact per-cell values are pinned by fixtures.
- Power set `linear`, `abs`, `sin`, `cos`, `inv`, applied element-wise to both
  coordinates. `inv` maps 0 to +Infinity by definition; `sin`/`cos` use the accepted
  bit-exact fdlibm trig. `tan`/`log`/`pow` are a documented follow-up, not an implied
  capability.
- A nonfinite iterate is a handled drop path: counted in `dropped`, running point
  resets to the next seed round-robin. A finite iterate outside the window is counted in
  `dropped`, deposits nothing, and the running point advances to it so the IFS dynamics
  continue. Every step is counted exactly once; `plotted + dropped == iterations`.
- Probability selection: cumulative weights, one accepted-LCG draw per step, least
  transform index with `target < cumulative[k]`. Transform array order is part of the
  contract; reordering changes the draw mapping and the buffer.
- Work is `iterations` in exact integers, precharged before allocation; the grid map and
  splat are constant-factor per iterate and do not grow work with grid size.
- NUMERIC_OVERFLOW is reserved; the transform may produce nonfinite as a drop path and
  the buffer is provably finite for valid inputs, so the code path is defensive, not
  expected.

Fixtures distinguish the corner single-cell deposit, the center bilinear quarter split,
right-edge clamping, exact-edge drop, RNG order under transform reordering, the `inv`
nonfinite reset, a sin/abs power mix, and the INVALID_INPUT/WORK_LIMIT carriers. This
contract freeze permits implementation; it is not native, artist recreation or
target-support acceptance.
