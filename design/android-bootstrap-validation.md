# Android runtime bootstrap

Before native adapter implementation, establish an actual Android app running the
pinned Processing Android 4.6.0 core (release android-412). Use SDK platform 33,
build tools 30.0.3, release-template AGP 7.1.0/Gradle 7.4.2 and local Java 17.
The isolated emulator uses Android 33 Google APIs x86_64 and software acceleration
if KVM is unavailable. Record installed package revisions and source/archive hashes.

The bootstrap app creates a 32×24 ANDROID2D PApplet via PFragment and reports the
actual renderer class, Android API, dimensions and successful setup to app-private
storage. It performs no art reproduction or adapter acceptance. One successful
bootstrap launch is enough; diagnose build/startup failures before retrying them.
Keep build output, SDK/emulator state, APK and debug signing key under `.work`.

This prerequisite does not permit claiming desktop Java conformance as Android
conformance. The eventual adapter requires a separate reviewed boundary and registered
pixel, lifecycle and CP1 validation against the native runtime.

Initial build reached debug signing and failed because a custom workspace-local
keystore is not automatically generated by AGP. Preserve that failed build report.
The preparer now generates the standard debug-only key at the configured ignored
path before building. No release signing identity or user keystore is involved.

The next compiler diagnostic found that this release has no `ANDROID2D` Java
constant. That name is our semantic backend identifier. Native `PConstants.JAVA2D`
is the release's compatibility token; `PApplet.makeGraphics()` recognizes it and
constructs `processing.a2d.PGraphicsAndroid2D` directly. Use that actual public token
in the bootstrap and continue asserting the resulting native class. Preserve the
compiler-failure report; no runtime or pixel acceptance was attempted by either build.
