# Slit Compositions (brief 34)

Status: **implemented on branch `w2/slit-compositions`, unreleased. Reviewed from rendered SVG output
only (headless Chromium); not yet exercised through the real Studio interface, layered in the app, or reviewed for
responsiveness there.** It builds on the merged [raster and image-structure foundation](composition-raster-structure.md)
(`Raster`, bundled sample rasters, `sampleInto`, content hashes) and the frozen
[reference slice](composition-reference-slice.md) and [structural operators](composition-structural-operators.md)
conventions. Guide: `packages/instruments/guides/slit-compositions.md`.

## Artist-facing brief

Time stretched into bands, or one image recomposed through slices with editable source correspondence. Two
methods share one mapping and are labelled honestly:

- **Slice one image.** A picture is cut into N parallel strips; each output band shows one of them.
- **Slit-scan a frame sequence.** A moving scene is read along one line (the slit) once per output band, at a different
  moment for each band, so time becomes distance across the picture.

The artist edits the correspondence, not just the look: ordering (sequence, reverse, comb, interleave, seeded
shuffle of a chosen fraction, cyclic phase shift), repetition (with alternate reversal), per-band offset and
scale (ramp, wave, alternate, random), the time curve (linear, power, swing or a recorded gesture), the time window
with explicit end behaviour, the slit's position, angle, bend and length, and a Region Quilt mask. A few unsliced
fragments keep the original in place for comparison. Output is vector bands, not marks: quantized runs of equal
colour, merged into single rectangles.

## Input contract (F3, image sequences)

No video, camera or codec is involved. There is no host video input yet, so the sequence is an owned, bounded,
resolved value the library defines:

- `FrameStack` (`composition/frame-stack.ts`): frozen ordered `Raster` frames with one timestamp per frame in SECONDS,
  strictly increasing; all frames share width, height, channels, format, colour space and alpha mode; 1 to 256 frames,
  at most 16,777,216 pixels in all. A missing or non-Raster frame, unequal frames and a non-increasing timestamp are errors naming the
  index; a missing frame is never replaced by a neighbour. `hash` is a SHA-256 over the frames' raster hashes and
  timestamps (documented in the module header, tested against `node:crypto`).
- **Time semantics are explicit.** `resolveFrameTime(stack, t, interpolation, end)` returns (frame, next, mix):
  interpolation `hold` (the earlier frame stays until the next timestamp), `nearest` (a tie takes the later frame) or `linear`
  (cross-fade; the sampler mixes in linear light); end behaviour `clamp`, `loop`, `mirror` or `fail` (throws, naming the time,
  the limits and the controls to change). A one-frame or zero-duration stack always resolves to its frame.
- **Bundled sequences** (`composition/frame-samples.ts`) stand in for decoded video: `walkers`, `sunrise`, `orbits`,
  `windmill`, 128 x 128 sRGB RGB frames generated by seeded closed-form code (IEEE arithmetic, `Math.sqrt`, `Math.floor`,
  a polynomial sine; no `Math.sin`), so bytes and hashes are identical on every engine (pinned in the tests). `frames`
  (2 to 240) samples a fixed duration more or less finely; it does not lengthen the scene. `orbits` and `windmill` are whole turns and loop.
- **Persisted instruments name only bundled sources.** The direct API and the typed recipe accept any resolved
  `Raster` (`source: { kind: "raster" }`) or `FrameStack` (`{ kind: "stack" }`). **Binding a host's own image or
  decoded frames to a Studio layer, and importing video, is future host work** (an asset field in the document, host-side decoding with
  size and security limits). Nothing here fetches, decodes or opens a file.

## Producers (frozen, cached by construction)

| Function | Result | Cache key |
|---|---|---|
| `bundledFrameStack(id, seed, frames)` | `FrameStack` | id, seed, frames (LRU 6) |
| `sliceTable(options, stack?)` | `SliceTable`: the output band -> source table | every option plus the stack's hash (LRU 16); never an appearance |
| `slitStrips(source, table, options)` | `StripSet`: 8-bit sRGB RGBA samples, one row per band | lives with the table; source hash, direction, footprint (images only), detail, outside policy, slit (stacks only) |
| `slitFragments(source, options)` | `FragmentSet`: unsliced windows | source hash and every option (LRU 6) |
| `quiltCells(mask, seed, w, h)` | retained clipping cells | the existing `partitionRegions` cache; `keep` filters afterwards |
| `slitRects(table, strips, fragments, options)` | frozen rectangles | not cached: pure and linear in samples (1-53 ms measured) |

Palette, colour mode, tone steps, threshold, gap, centre and rotation are never keys, so appearance edits reuse
every producer (tested by object identity). `detail` and the footprint size resample without re-mapping (the table is kept).

### The slice table

`SliceTable.rows` is in output order. Each row: `id`, `seed`, `source` (the source slice index), `repeat`, `slot`
(output band), `across` (the band's fractions of the across axis), `interval` (the source slice `[s/N, (s+1)/N]` across
the image, or along the time parameter), `time` (`progress`, `time` in seconds actually read, `frame`, `next`, `mix`; `null`
for one image), `offset` and `scale`.

- **Stable ids.** A slice's id is `slice:NNN` from its SOURCE index; repeats add `:rK`. Reversing, shuffling and shifting move
  rows and never rename them; a repeat of a slice draws from the same stream (`componentSeed(seed, id, purpose)`), so a
  repeat is an exact echo. Changing the slice count replaces the ids, intentionally. Fragments are `fragment:NN`, each
  drawing its own position and size from that id, so adding fragments never moves the others. Quilt leaves keep their ids
  and rectangles when `keep` changes.
- **Orders.** `comb(k)`: slices 0, k, 2k, ... then 1, k+1, ...; `interleave(k)`: `ceil(N/k)`-long groups riffled one from each
  in turn; `shuffle`: a `disorder` fraction of slices, chosen by their own ids, trade places among themselves in the order of their id hashes;
  `phase` rotates the result left by `round(phase x N)`. Each is a permutation (property test over random sizes).
- **Offset and scale** act along the band's length: content at source position `p` lands at `0.5 + (p - 0.5) scale + offset`. Ramp, wave and
  alternate act by output slot (they stay put when the order changes); random acts by slice id (travels with the slice).
- **Beyond the source** (`clamp`, `wrap`, `mirror`, `void`) decides what a position outside [0, 1] reads; `void` is transparent. A slit point outside the frame is always void.

### Sampling and colour

Strips are sampled with `sampleInto` (the foundation), premultiplied in linear light, stored as straight 8-bit sRGB. Images are fitted to the footprint by
`cover`. A slit is a parabola-bent line in frame pixels. Alpha is thresholded at one half because bands are opaque fills.
`slitRects` quantizes (source colour per channel, tonal ramp of luma through the palette, or single-colour ink below a luma threshold), merges consecutive equal samples into runs, and,
with no gap, merges runs of neighbouring bands with identical extent and colour. Mask cells clip rectangles exactly. `drawSlit` fills every rectangle
with a 0.3-unit spill on each side so antialiasing opens no seams (a gap of g is therefore drawn g - 0.6 units wide).

## Controls (49) and groups

Groups: **Source** (Method, Source image, Source scene, Frames, Between frames), **Slices** (Band direction, Slices, Repeats, Repeat order;
subgroup **Order**: Order, Groups, Disorder, Phase shift), **Time map** (Time curve, Power, Swings, Gesture, Gesture channel; subgroup **Window**: start,
length, Past the ends), **Slit** (position, angle, bend, length), **Shaping** (subgroups **Offset**, **Scale**; Beyond the source), **Fragments**,
**Mask**, **Placement** (centre, proportional **Size**, rotation), **Drawing** (Detail, Color, Tone steps, Ink threshold, Gap). Only Size is proportional: width and height share one unit and
scaling them together is one edit; Offset/Scale amounts are in different units (fraction of length, octaves) and nothing else in the instrument shares a unit.

Conditional (inline `visibleWhen`): Source image under Slice one image; Source scene, Frames, Between frames, the whole Time map, Slit and Fragment moment under
Slit-scan; Power, Swings, Gesture, Gesture channel under their time curve; Groups under comb or interleave; Disorder under shuffle; Offset/Scale amounts under any
pattern but None and their periods under Wave; Tone steps except under Ink; Ink threshold under Ink; the three Quilt controls under a quilt mask. A test changes every hidden control under the
driver combinations and requires an identical drawing. The control audit (`tests/helpers/audit-controls.ts --child slit-compositions`: 16 drivers, 30 contexts, 2,376 probes) reports 0 violations, 19 controls that always matter, Beyond the source as disjunctive
(it matters only when offset or scale carries a band past the source, or a slit leaves the frame), and Repeat order and Past the ends as inert in every sampled context (one repeat; a window that fits the sequence). All three stay visible on purpose: relevance depends on numeric values a conjunctive condition cannot state. Fragment size is likewise inert with no fragments.

## Defaults, ranges and creative review

Default: Portrait, 96 columns, shuffle 10%, wave offset 5% (period 40), two fragments of about a quarter of the footprint, source colours at 8 steps, detail 96, centred 460 x 460.
Slider intervals are ranges that read well (Slices 4-160, Repeats 1-6, Detail 12-160, Frames 8-96); hard limits are the bounds above.

Rendered and read (SVG through Chromium; see the report for the defects found): defaults on Portrait, Geometry and Landscape, three seeds, all four scenes at their defaults
and at a second seed, and twelve strongly different settings (recorded-gesture time map with rows, comb with alternating repeats, quilt mask with rotation and ramp,
interleave with wave scale and mirror, dense 320 x 260 shuffle, sparse gapped columns, horizontal slit through the windmill hub, looped window with a bent slit,
ink, and combined reverse/phase/ramp/random/void), plus three layered pairs with unmodified instruments in both orders (contour scores, motif ecologies, region quilts).
The default portrait stays recognisable in all three seeds. Extreme settings (dense shuffle, ink on the walkers) deliberately lose the subject.

## Limits and open decisions

- No video, camera or codec; no host binding of a user's image or frames (future host work); bundled scenes are synthetic, not footage.
- Slice directions are the two axis-aligned ones plus footprint rotation; curved or radial slicing would need clipping the strips to non-rectangular cells and is not offered. A slit is a line or parabola, not an arbitrary polyline.
- Region Quilt masking uses the existing rectangular partition (`partitionRegions`, longest-side cuts, bias -0.2 fixed); arbitrary polygon masks await the planar-domains foundation.
- The time map takes a bundled recording's own timing, not a host-supplied recording; the direct function API takes any `TimeCurve` inputs but the gesture curve names a bundled recording.
- Bands are opaque rectangles, so a soft or anti-aliased source edge is quantized; alpha is thresholded at 0.5 and there is no partial coverage.
- Existing bug not caused here: `canPrepareInstrument` in `src/index.ts` has an unreachable duplicate `return` that leaves Data Scores reporting `false`; this study only added itself to the reachable line.
