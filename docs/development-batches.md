## Cost and quality controls

- Give workers the relevant files and a short brief, not the entire conversation.
- Reuse accepted fixtures, runners and builders. Add cases for distinct observable
  risks, not to increase test counts or mirror implementation branches.
- Run focused checks after changes; run broader checks at integration. Do not rerun
  unchanged successful renders or benchmarks without a specific unresolved concern.
- Review a coherent diff once; reopen only changed or disputed parts. Escalate contract
  ambiguity and substantive failures rather than every implementation iteration.
- Report delivered capabilities, remaining acceptance work and actual failures. State
  when numerical comparisons are repetitions of a few scenarios.
- Track tool-reported usage if available. Do not infer weekly balance, money saved or
  completion time from model names, assertion counts or the automatic goal counter.

The full-roadmap percentage remains a rough planning estimate. Completed package slices
and outstanding deliverables are the actionable progress measure.
