# p5.js browser capability constraints

Verified 2026-09-17 against the project checkout and the official p5.js reference. The web package pins `p5: 2.3.2` in [apps/web/package.json](../apps/web/package.json); the installed runtime reports 2.3.2 in both `apps/web/node_modules/p5/package.json` and `.work/environments/p5js/node_modules/p5/package.json`. The browser workflow uses the isolated [layer runner](../tools/harness/run_p5_layer.mjs), Chromium via Playwright, a 640×640 viewport, pixel density 1, same-origin source serving, and Chromium `--disable-gpu`.

## What p5 supplies

| Capability | Browser fact and caveat | Implication for a future p5-only study |
|---|---|---|
| Framebuffer / ping-pong | `createFramebuffer()` is WebGL-only and creates a texture-backed `p5.Framebuffer` in the same WebGL context. It supports `begin/end`, `draw`, `get`, `loadPixels/updatePixels`, configurable `UNSIGNED_BYTE/FLOAT/HALF_FLOAT`, RGB/RGBA, depth/stencil, filtering, resize and autosizing. The API has no named ping-pong/swap primitive; two buffers and an explicit swap remain sketch code. Its default Y orientation is flipped relative to images, and `LINEAR` filtering is the default. [createFramebuffer](https://p5js.org/reference/p5/createFramebuffer/), [Framebuffer](https://beta.p5js.org/reference/p5/p5.framebuffer/), [loadPixels](https://p5js.org/reference/p5.Framebuffer/loadPixels/) | A feedback effect can use two framebuffers, but acceptance must fix dimensions, density, format, filtering, clear order, swap order and orientation. Floating formats and WebGL extensions are browser-dependent. |
| Shaders | `createShader`/`shader` compile GLSL on the GPU. Shaders only work in WebGL; only filter shaders can be used in 2D mode. `p5.Shader.version()` distinguishes GLSL `100 es` and `300 es`; WebGL 1 is GLSL ES 1.00 and WebGL 2 may use either. Compilation, precision, extensions and output can vary by browser/driver. [createShader](https://p5js.org/reference/p5/createShader/), [p5.Shader](https://p5js.org/reference/p5/p5.Shader/), [shader](https://p5js.org/reference/p5/shader/) | Shader algorithms are a renderer capability, not portable package computations. A study needs a fallback or a declared WebGL profile, explicit shader source, uniforms, precision and a browser matrix. Headless `--disable-gpu` evidence is a software-renderer check, not cross-GPU equivalence. |
| Custom geometry / normals | `beginShape`/`endShape` and `vertex` make custom 2D/3D shapes. In WebGL, `normal()` sets the normal for following vertices and lighting uses it; `p5.Geometry` exposes vertices, faces, `uvs`, vertex normals, `computeFaces`, `computeNormals`, `buildGeometry`, and `model()`. Transform calls cannot occur between `beginShape` and `endShape`. [normal](https://p5js.org/reference/p5/normal/), [endShape](https://p5js.org/reference/p5/endShape/), [p5.Geometry reference](https://p5js.org/reference/) | Procedurals can supply positions/indices/normals as data, while p5 owns upload/draw. Winding, flat versus computed normals, duplicate vertices, face order and lighting state must be fixed by the study; p5 does not provide a general mesh authoring contract. |
| UV / textures | Custom WebGL vertices need UV arguments (`vertex(x,y,z,u,v)`) for `texture()`. `textureMode(NORMAL)` changes UVs to 0..1; default `IMAGE` uses image dimensions. [textureMode](https://p5js.org/reference/p5/textureMode/) | UV generation is still custom per mesh/algorithm. Acceptance must set texture mode, image dimensions, Y orientation and filtering explicitly. |
| Font outlines and text points | `loadFont()` creates `p5.Font`; current p5 reference exposes `textToPoints`, `textToContours`, `textToPaths` and `textToModel`. `textToPoints` returns sampled `{x,y,alpha}` points with `sampleFactor` and `simplifyThreshold`; sampling is approximate and font-dependent. WEBGL text supports fonts loaded with `loadFont()`. [textToPoints](https://beta.p5js.org/reference/p5.font/texttopoints/), [textFont](https://p5js.org/reference/p5/textFont/), [reference index](https://p5js.org/reference/) | p5 can support a study that ships a known font asset. Font loading, glyph metrics, shaping, kerning, Unicode behavior, outline tessellation and point sampling remain asset/renderer concerns; a general typography operation still requires custom scope and evidence. |
| Audio / FFT | Audio is an addon (`p5.sound`), separate from the pinned core `p5` dependency. `p5.FFT` analyzes short snapshots; current reference constrains FFT size to powers of two 16..1024. Web Audio requires browser permissions/autoplay handling and timing is live. [p5.sound](https://p5js.org/reference/p5.sound/), [p5.FFT](https://p5js.org/reference/p5.sound/p5.FFT/) | Audio-reactive art needs an explicit addon version, input/file policy, sample rate/channel assumptions, smoothing/bin mapping and a prerecorded deterministic fixture for acceptance. Live microphone analysis cannot establish exact replay pixels. |
| Offscreen rendering | `createGraphics(w,h,P2D|WEBGL)` creates an offscreen `p5.Graphics`; WebGL graphics use WebGL2 when available and can be forced to WebGL1 with `setAttributes({version:1})`. Graphics buffers need their own reset of transforms/lighting. [createGraphics](https://beta.p5js.org/reference/p5/createGraphics/), [p5.Graphics](https://p5js.org/reference/p5/p5.Graphics/) | Offscreen composition is available, but each buffer has renderer/context/memory costs. Fix renderer, dimensions, density, reset state and copy orientation. `createFramebuffer` is generally faster as a WebGL texture than a graphics buffer. |
| WebGL 1/2 | `setAttributes({version:1|2})` requests a context; default requests WebGL2 and falls back to WebGL1 if unavailable. `webglVersion` reports `webgl2`, `webgl` or `p2d`. Attributes include antialias, depth, stencil, alpha, premultipliedAlpha and preserveDrawingBuffer. Calling `setAttributes` after canvas creation reinitializes the context. [setAttributes](https://beta.p5js.org/reference/p5/setAttributes/), [webglVersion](https://p5js.org/reference/p5/webglVersion/) | A capability depending on WebGL2, float render targets, derivatives or GLSL 300 must declare that dependency and test fallback behavior. Context loss, driver differences and software rendering are material risks. |
| Saving | `saveCanvas` downloads PNG, WebP or JPEG (or prompts via browser); `saveFrames` downloads/callbacks PNG/JPEG sequences but clamps duration to 15 seconds and frame rate to 22, with memory warnings for large canvases. [saveCanvas](https://p5js.org/reference/p5/saveCanvas/), [saveFrames](https://p5js.org/reference/p5/saveFrames/) | Browser download is a UI side effect, not a portable operation output. The project’s harness checks cached PNG/save behavior in selected workflows; future acceptance should inspect bytes, dimensions and event completion, while treating browser file dialogs as integration behavior. |

## Determinism limits

`randomSeed()` makes p5 `random()` and `randomGaussian()` repeatable within a sketch; `noiseSeed()` makes p5 `noise()` repeatable across runs. This does not guarantee identical pixels across browser engines, p5 versions, fonts, device pixel ratios, GPU/software paths, shader precision, audio clocks, asynchronous asset loading or frame timing. [randomSeed](https://p5js.org/reference/p5/randomSeed/), [noiseSeed](https://p5js.org/reference/p5/noiseSeed/).

The existing harness fixes source hashes, p5 bundle hash, package source hashes, viewport, density, seeds and tick in the job spec, and blocks network requests. It launches Chromium headless with `--disable-gpu`; that is useful for a stable controlled run but is not evidence of GPU/WebGL portability. For animated or feedback work, acceptance must also fix frame count, update order, framebuffer clear/swap semantics, `frameCount`/time inputs, and any asynchronous setup completion. Exact pixel checks should remain renderer-profile specific; structural or perceptual checks are more appropriate when shaders, text, WebGL or assets are material.

## Where custom algorithms remain necessary

p5 supplies the browser substrate and drawing calls. It does not supply Procedurals-level algorithms such as a general ping-pong simulation schedule, deterministic fluid/boid solver, SDF/CSG, arbitrary mesh generation, font shaping policy, audio-to-geometry mapping, or cross-renderer numeric contracts. Those remain custom sketch/package computations and must be scoped independently. Existing `packages/javascript/src/` operations can provide data to p5, but a p5 feature’s existence does not establish Procedurals operation acceptance.

## Practical constraints for future p5-only expansion

Use the pinned p5 2.3.2 runtime and the existing isolated runner. Keep renderer-dependent work in examples/adapters, with explicit WebGL1/WebGL2 and P2D paths where relevant. For every new study, record the exact browser/runtime profile, seed/noise/time inputs, asset hashes and frame lifecycle; test reset/reload/save through the existing browser workflow; and separate exact pixel evidence from technique-level or visual evidence. For framebuffer/shader studies, include a no-feedback baseline and explicit resource bounds. For typography/audio, ship or hash deterministic assets/fixtures and avoid treating live timing as exact replay evidence. No new engine is required for these capabilities, but unsupported browser or addon behavior must be identified before claiming it.
